# 开发与发布

本文面向维护者，说明本项目的开发环境、验证命令、构建流程和 GitHub 发布方式。

## 一、开发环境

建议环境：

- Windows 10/11 x64
- JDK 21，需包含 `jpackage`
- Maven
- PowerShell 7
- 可访问网络，用于首次下载 Maven 依赖和 Playwright Chromium

普通用户运行发布包时不需要单独安装 Java 或浏览器。

## 二、提交前检查

```powershell
mvn -DskipTests=false test
```

测试覆盖内容包括：

- 配置默认值与规范化。
- 冷却与每日上限策略。
- `pom.xml`、`plugin.yml`、`build/version.json` 版本同步。
- 内置浏览器查找逻辑。
- 离线页面选择器兼容性。

## 三、构建发布包

```powershell
pwsh -ExecutionPolicy Bypass -File .\build.ps1
```

构建脚本会执行以下步骤：

1. 从 `build/version.json` 读取当前版本并递增补丁号。
2. 同步更新 `pom.xml`、`plugin.yml`、`build/version.json`。
3. 校验三处版本完全一致。
4. 清空 `PLUGIN` 目录。
5. 执行 Maven 测试与打包。
6. 下载或复用可打包的 Chromium 浏览器。
7. 优先使用 `jpackage` 生成 Windows 程序镜像；不可用时生成包含完整 Java 运行时的便携目录。
8. 写入发布包内的 `使用说明.txt` 和 `启动诊断.cmd`。
9. 只把本次生成的 `douyin-auto-spark-*-windows.zip` 放入 `PLUGIN` 目录。

## 四、版本规则

凡是需要构建时，必须保证版本号递增并同步到以下文件：

- `pom.xml`
- `plugin.yml`
- `build/version.json`

如果只修改文档且不构建，不需要递增版本号。

## 五、产物管理

- `target`、`build`、`PLUGIN` 属于本地构建输出，不建议提交到 Git。
- 发布给用户的压缩包建议上传到 GitHub Releases。
- 每次涉及插件产物更新时，必须先清空 `PLUGIN` 目录，再仅复制本次改动对应的产物。
- 不要只分发 `.exe`；必须分发完整压缩包。

## 六、GitHub 首次上传流程

如果本地还不是 Git 仓库，可按以下方式初始化并上传：

```powershell
git init
git remote add origin git@github.com:uxu2023259/AutoDouyinSpark.git
git add .
git status
git commit -m "初始化抖音自动续火花助手仓库文档"
git branch -M main
git push -u origin main
```

如果远程仓库已有内容，请先拉取并处理冲突：

```powershell
git remote add origin git@github.com:uxu2023259/AutoDouyinSpark.git
git fetch origin
git status
```

确认无误后再提交和推送。

## 七、自动发布到 GitHub Releases

仓库包含 `.github/workflows/auto-release.yml`，默认在 `main` 分支出现以下路径变更时自动发布：

- `app/**`
- `pom.xml`
- `plugin.yml`
- `build.ps1`
- `build/version.json`

工作流会自动执行：

1. 检出 `main` 分支。
2. 设置 JDK 21 和 Maven 缓存。
3. 执行 `build.ps1`，递增版本、运行测试、打包程序并生成 `PLUGIN\douyin-auto-spark-*-windows.zip`。
4. 提交 `pom.xml`、`plugin.yml`、`build/version.json` 的版本号变更。
5. 创建 `v版本号` 标签并推送到 GitHub。
6. 创建 GitHub Release 并上传本次构建的 Windows 压缩包。

首次使用前，请在 GitHub 仓库中确认：Settings → Actions → General → Workflow permissions 已设置为 `Read and write permissions`。如果开启了分支保护，需要允许 GitHub Actions 向 `main` 分支推送版本提交和标签。

也可以在 GitHub Actions 页面手动运行“自动构建并发布版本”工作流。

## 八、手动发布到 GitHub Releases

1. 执行 `build.ps1` 生成新版压缩包。
2. 在 GitHub 仓库页面创建新 Release。
3. 标签必须与构建版本一致，例如 `v1.0.53`。
4. 上传 `PLUGIN\douyin-auto-spark-*-windows.zip`。
5. 在 Release 说明中写明主要改动、使用方式和注意事项。

## 九、维护注意事项

- 所有新增或修改文件必须使用 UTF-8 保存。
- 所有面向用户的外显文本必须使用中文。
- 不要提交真实登录态、日志、失败截图或包含隐私信息的页面快照。
- 调整抖音页面选择器时，优先增强兼容层，不要推翻当前稳定发送策略。
- 不要恢复“匹配多个即报错”或“未确认标题即禁止发送”的旧策略。
