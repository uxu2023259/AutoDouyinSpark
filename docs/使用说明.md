# 使用说明

本文面向普通使用者，说明如何安装、管理多个账号、登录、配置和排查抖音自动续火花助手。

## 一、下载与解压

1. 从 GitHub Releases 下载 `douyin-auto-spark-*-windows.zip`。
2. 右键压缩包，选择“全部解压”或使用解压软件完整解压。
3. 解压后应能看到 `启动诊断.cmd`、`使用说明.txt`、`app`、`runtime`、`browsers` 等内容，并且至少包含 `抖音自动续火花助手.exe` 或 `抖音自动续火花助手.bat` 中的一个启动入口。
4. 不要只复制单个启动入口，也不要直接在压缩包里双击运行。

## 二、首次启动与登录

1. 优先双击 `抖音自动续火花助手.exe`；如果发布包内没有 `.exe`，请双击 `抖音自动续火花助手.bat`。
2. 如果没有窗口，请双击 `启动诊断.cmd` 查看中文诊断提示。
3. 在左侧账号工作区选择要登录的账号，再点击“打开登录/聊天页”。
4. 在弹出的内置 Chromium 浏览器中完成抖音创作者中心登录。
5. 登录成功后保持程序运行至少 15 秒。程序会将抖音会话型登录凭据转换为 180 天持久凭据，并继续保存在当前账号的 Chromium 加密资料目录中；切换账号不会复用该登录态。

程序不会绕过扫码、验证码、风控或任何账号安全校验。登录失效时，请重新点击“打开登录/聊天页”并手动完成验证。

## 三、多账号工作区

- “新增账号”会创建一套完全独立的配置、状态、浏览器登录态和截图目录。
- 账号名称用于界面识别，账号 ID 用于稳定存储；重命名不会丢失原登录态。
- “归档账号”会停止该账号并把完整数据移动到 `archived-accounts`，不会直接删除。
- 至少保留一个账号；同名账号会被拒绝，避免操作混淆。
- 所有已启用账号均有独立调度器；同时运行的账号越多，发送期间资源占用越高。自动任务结束后会释放对应 Chromium。
- 从旧版本首次升级时，原 `config.json`、`state.json`、`browser-profile` 和 `screenshots` 会迁移到“默认账号”。

## 四、配置项说明

| 配置项 | 说明 | 建议值 |
| --- | --- | --- |
| 启用状态 | 是否允许当前账号每天按计划发送。 | 启用 |
| 指定用户 | 每行填写一个完整用户名；多个不同身份的完全同名会话会逐个尝试发送。 | 使用会话列表中的完整名称 |
| 每日发送时间 | 每天开始处理名单的本机时间，格式为 `HH:mm`。 | 16:00 |
| 发送内容 | 每天从指定时间开始处理；未确认目标会持续重试，可能重复发送。 | 简短明确的消息 |
| 全局启动 | 是否在 Windows 登录后启动程序并守护所有启用账号。 | 按需开启 |
| 自动发送浏览器 | 默认使用无界面 Chromium；完成名单处理后关闭浏览器以释放内存。关闭此项可在发送期间显示浏览器。手动打开的登录窗口始终保持可见。 | 开启，减少资源占用 |

填写完成后点击“保存当前账号配置”。程序会在设定时间开始处理名单；没有手动立即发送入口。

“发送策略”页面底部始终提供“保存当前账号配置”按钮；也可以按 `Ctrl+S` 保存。保存只作用于左侧当前选中的账号。

## 五、目标会话匹配策略

目标会话按以下方式处理：

- 列表中的名称按去除首尾空格、合并连续空格并忽略大小写后做完整比较；相似名称和包含匹配不会被选中。
- 多个不同会话身份拥有完全相同的名称时，程序会逐个尝试发送，以降低漏发；这可能向多个同名用户发送相同消息。
- 每行是一个独立目标；逐行处理和保存结果，不会因为另一位用户失败而跳过后续用户。
- 切换会话后必须通过标题、选中态或目标节点状态确认；无法确认时不会发送。
- 每次发送只触发一次“发送”按钮，降低页面延迟时重复发送的风险。
- 只有在正确会话中检测到发送前不存在、文本完全一致的己方新消息气泡才确认成功；输入框清空和接口响应仅作辅助证据。
- 暂时找不到用户、发送失败或结果不确定都会单独写入本日状态并持续重试；身份相同的重复页面记录只处理一次。

## 六、每日发送与异常处理

- 每个账号每天只有一个计划时间；到时后按配置顺序处理每位用户。
- 程序当天晚启动或从短暂故障中恢复时，会继续处理所有未确认用户。
- 只有发送结果核验成功才停止当天重试；失败、未找到或结果不确定会持续重试，不设次数上限。
- 重试间隔从 1 分钟开始按 1、2、4、8、16、32 分钟递增并封顶 60 分钟，避免短时间重复触发。
- 如果程序在发送过程中关闭，未确认状态和尝试次数会保留；程序重新运行后会按退避时间恢复处理。
- 登录失效、账号目录被占用或出现安全验证时会暂停后续用户。完成人工处理后点击“解除人工暂停”；该按钮只恢复计划，不会立即发送。
- 日志逐人记录结果。顶部显示“今日确认”和“待确认”数量；所有目标及同名候选都确认后才会显示全员成功。

## 七、运行状态与数据目录

默认数据目录为 `%APPDATA%\DouyinAutoSpark`。

| 内容 | 路径 |
| --- | --- |
| 账号注册表 | `%APPDATA%\DouyinAutoSpark\accounts.json` |
| 账号配置 | `%APPDATA%\DouyinAutoSpark\accounts\<账号ID>\config.json` |
| 账号状态和逐用户本日结果 | `%APPDATA%\DouyinAutoSpark\accounts\<账号ID>\state.json` |
| 账号登录态 | `%APPDATA%\DouyinAutoSpark\accounts\<账号ID>\browser-profile` |
| 日志目录 | `%APPDATA%\DouyinAutoSpark\logs` |
| 失败截图 | `%APPDATA%\DouyinAutoSpark\accounts\<账号ID>\screenshots` |
| 归档账号 | `%APPDATA%\DouyinAutoSpark\archived-accounts` |

如需重新登录，可以关闭程序和浏览器后，仅删除对应账号目录中的 `browser-profile`，再重新启动并登录。不要删除其他账号的资料目录。

## 八、日常使用建议

- 首次登录需要可交互 Windows 桌面；自动发送默认在无界面模式运行，无须让浏览器窗口常驻。
- 自动发送默认使用无界面 Chromium，并在当日名单处理结束或暂停后关闭浏览器；下次计划任务会按需重新启动。
- 如果显式点击“打开登录/聊天页”，浏览器窗口会保持打开供手动登录和检查；关闭窗口后，后续任务按“自动发送使用无界面浏览器”选项运行。
- 程序运行期间会定期加固登录态，主动重建浏览器和正常退出前也会再次落盘；抖音主动注销、账号安全策略或服务端令牌失效仍需重新验证。
- 无界面自动任务不依赖浏览器窗口置前、页面可见性或人工刷新。
- 多账号同时运行会占用更多内存，建议服务器按账号数量预留 Chromium 运行资源。
- 新增账号后先完成登录，并核对目标用户全名、每日时间和消息内容，再启用每日发送。
- 检查日志中的“已发送并确认”“未找到”“结果不确定”等逐人状态；不确定结果可能导致重复消息。
- 如果抖音页面提示安全验证，请先手动完成验证。
- 如果页面结构变化导致失败，请保留日志和失败截图用于排查。
